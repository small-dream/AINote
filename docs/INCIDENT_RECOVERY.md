# 故障恢复手册（M1-E3-T4）

> 面向用户的「用户操作 → 预期结果」手册，覆盖断网、崩溃、误删、仓库损坏、凭证失效、磁盘不足六类场景。
> 附带自动化演练：`pnpm test:drills`（`cargo test drill -- --nocapture`），可重复运行。

## 0. 通用原则

1. **先别删东西。** 本地仓库是完整 Git 仓库，绝大多数故障都能从 `.git` 或备份恢复。
2. **先看一眼状态。** 设置 → 仓库 → 「检查完整性」给出只读诊断与修复建议；设置 → 诊断与反馈 → 「导出诊断包」用于求助。
3. **能备份先备份。** 设置 → 仓库 → 「导出整库备份」可随时导出一个自包含 zip（含 `.git` 与 `manifest.sha256`）。

## 1. 断网 / 同步失败

| 项 | 内容 |
|---|---|
| 现象 | 同步按钮报错，状态栏提示网络不可达或超时（`SYNC_4002`） |
| 原因 | 无网络、代理不可达、GitHub 暂时不可用 |

**用户操作**

1. 继续离线编辑——笔记先存本地，不会丢。
2. 恢复网络后点击「同步」。
3. 反复失败时：设置 → 诊断与反馈 → 导出诊断包，附到 Issue。

**预期结果**：同步成功，`ahead/behind` 归零；失败期间本地文件内容始终完整。

> 自动化：`drill_save_failure_keeps_original_content` 覆盖「写失败不丢内容」；同步阶段的错误分类见 `M1-E4-T1`。

## 2. 应用崩溃 / 强制退出

| 项 | 内容 |
|---|---|
| 现象 | 应用白屏或异常退出 |

**用户操作**

1. 重新打开应用；崩溃页面提供「重试 / 导出诊断包 / 返回工作区」。
2. 检查最近编辑的笔记是否有未保存内容（编辑器 3s 防抖保存）。
3. 未保存内容丢失时，从备份恢复（见 §4）。

**预期结果**：重启后工作区正常打开；已落盘的笔记内容与崩溃前一致；崩溃信息写入本地日志并可导出。

## 3. 误删笔记

| 项 | 内容 |
|---|---|
| 现象 | 笔记或目录被删除 |

**用户操作**

1. 打开侧栏「回收站」。
2. 找到目标条目，点击「恢复」。

**预期结果**：笔记回到原路径，内容不变；若原路径已被占用，自动追加序号，不覆盖现有文件。

> 自动化：`drill_deleted_note_restores_from_trash`。

## 4. 仓库损坏（对象损坏 / 索引损坏）

| 项 | 内容 |
|---|---|
| 现象 | 打不开仓库、同步报错、完整性检查报 `REPO_3102`（对象损坏）或 `REPO_3103`（索引异常） |

**用户操作**

1. 设置 → 仓库 → 「检查完整性」，确认问题码与修复建议。
2. 有备份：设置 → 仓库 → 「从备份恢复」，选择备份 zip，恢复为一个新仓库。
3. 无备份但远端完好：备份本地未同步的笔记文件后，移除仓库并重新绑定 GitHub 远端。
4. 恢复后再次执行「检查完整性」，确认无 `error` 级问题。

**预期结果**：恢复出的仓库可正常打开，笔记内容与 Git 历史与备份时一致；损坏仓库不被二次修改。

> 自动化：`drill_corrupted_repo_recovers_from_backup`（备份 → 破坏 `.git/objects` → 报警 → 恢复 → 复检健康）。

## 5. 凭证失效

| 项 | 内容 |
|---|---|
| 现象 | 提示 GitHub 凭证失效（`SYNC_4003`） |

**用户操作**

1. 在 GitHub 生成具备 `repo` 权限的新 Token。
2. 应用内退出登录后重新连接 GitHub。
3. 重新同步。

**预期结果**：同步恢复；Token 仅存系统钥匙串，日志与诊断包中始终为脱敏值。

## 6. 磁盘不足

| 项 | 内容 |
|---|---|
| 现象 | 保存、导入附件或导出备份失败 |

**用户操作**

1. 查看剩余空间（见 `docs/TROUBLESHOOTING.md` §5）。
2. 设置 → 诊断与反馈 → 「清理日志」。
3. 检查仓库内 `assets/` 大文件，必要时迁移。
4. 释放空间后重试保存 / 同步 / 备份。

**预期结果**：操作成功；备份失败时不会留下半成品 zip，原仓库不受影响。
