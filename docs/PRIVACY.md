# 隐私与数据说明

> 适用版本：M1（v0.25）及以后。本文描述的是**实际实现的行为**，与代码一一对应；如发现不一致，请按「设置 → 诊断与反馈 → 导出诊断包」提交反馈。
>
> 一句话总结：**你的笔记只存在你的设备和你的 Git 仓库里；应用不向任何服务器发送笔记内容，也没有任何远程上报。**

## 1. 采集范围（本机使用计数）

应用默认在本机记录少量**使用事件**，用于判断真实使用情况与同步健康度。事件白名单固定为 7 个（新增事件必须评审并更新本文）：

| 事件 | 触发时机 |
|---|---|
| `app_launched` | 应用启动 |
| `repo_bound` | 首次绑定/克隆仓库成功 |
| `note_created` | 新建笔记 |
| `sync_succeeded` | 一次同步成功 |
| `sync_failed` | 一次同步失败 |
| `ai_action_confirmed` | AI 生成结果被确认落笔 |
| `update_checked` | 检查更新 |

每条记录只包含：**事件名、日期、时间戳**，以及快照级别的**平台名与应用版本**（例如 `macos` / `0.25.0`）。

**不采集**（结构上就没有对应字段）：

- 笔记正文、标题、标签、双链等任何内容；
- 文件路径、仓库名与仓库远端 URL；
- GitHub Token、AI API Key、任何凭证；
- 设备标识、IP、位置、使用时长明细。

聚合口径：近 7 天的「活跃天数」与「同步成功率」（成功次数 ÷ 成功+失败次数）。每日明细最多保留最近 56 天，超出的按天滚动删除；累计计数保留。

## 2. 存储位置

- 文件名：`metrics.json`，位于应用的**配置目录**（`app_config_dir`）：
  - macOS：`~/Library/Application Support/dev.ainote.app/metrics.json`
  - Windows：`%APPDATA%\dev.ainote.app\metrics.json`
  - Linux：`~/.config/dev.ainote.app/metrics.json`
  - Android：应用私有配置目录（其他应用无法读取）
- 格式：明文 JSON（内容本身不含敏感信息，无需加密）。
- 它**不在**你的笔记仓库里，不会随 Git 提交或同步，也不进入诊断包以外的地方（诊断包中含错误码计数摘要，不含本文件）。

## 3. 关闭方式

**设置 → 诊断与反馈 → 本机使用计数**，把开关关掉即可。

- 关闭后**立即停止写入**任何新事件（`metrics_record` 与内部埋点共用同一开关判断）。
- 已记录的历史计数仍然保留，直到你手动清空（见下节）。
- 开关状态保存在本机配置（`ainote.json`），重启后保持。
- 首次打开设置时会显示一次说明；点「知道了」后不再重复提示。

## 4. 删除方式

**设置 → 诊断与反馈 → 清空本机计数**：删除 `metrics.json`，计数回到 0，操作不可撤销（只删除计数，不影响笔记）。

卸载应用并删除上面的配置目录，同样会彻底移除这些数据。

## 5. 导出

**设置 → 诊断与反馈 → 本机使用计数 → 导出 JSON / CSV**。只有你主动点击才会写出文件，保存位置由你在系统保存对话框中选择：

- **JSON**：与第 1 节的采集范围一致——schema 版本、开关状态、平台与应用版本、更新时间、各事件累计次数与首次时间、每日明细，以及活跃天数与同步成功率两个窗口指标。
- **CSV**：`events` 段逐事件列出计数与首次时间，`summary` 段列出平台、版本、开关与两个窗口指标。

导出内容不含笔记内容、路径、远端地址与凭证；**取消保存不会生成任何文件，也不会报错**。导出的文件由你自行保管，应用不会读取或上传它。

## 6. 远程上报

**当前版本没有任何远程上报**：应用不会把日志、计数或笔记发送到任何服务器。设置页明确标注「没有远程上报」。

若未来引入可选的崩溃/指标上报（M1b / `M1-E2-T4`），必须满足：默认关闭、显式同意、可随时关闭并删除队列、单独的隐私说明，且仍然不采集笔记内容与凭证。

## 7. 与日志、诊断包的关系

- **本地日志**：默认写入平台日志目录（滚动保留 4 个文件），内容经统一脱敏（Token / API Key / Authorization / URL 凭据 / 用户目录）。可在「诊断与反馈」关闭或清理。
- **诊断包**：只有你主动导出时才生成，内容为版本、平台、配置摘要、同步状态、仓库大小、错误码统计与脱敏日志；**不含笔记正文、凭证与完整路径**。
- 两者都不会自动上传。

## 8. 加密笔记的设备级快速解锁（默认关闭）

加密笔记的仓库主密钥默认只存在于本次运行的进程内存里，退出应用即失效。你可以在「设置 → 加密笔记」显式开启**设备级快速解锁**，之后用系统的身份验证（Touch ID / Face ID / 指纹 / 设备密码）直接解锁，不必每次输入仓库口令。

- **存储位置**：平台安全存储——macOS 登录钥匙串、iOS Keychain（受访问控制保护）、Android Keystore（密钥材料不出 TEE，密文在应用私有目录）；条目名是仓库路径的哈希，见不到明文路径。
- **本机标记**：应用配置目录下的 `quick-unlock/<条目>.json`（0600、原子写），只记录「本机已开启 + 绑定的仓库密钥指纹 + 认证方式」，不含密钥。状态查询读它，因此不会凭空弹出认证界面。
- **不出去**：条目与标记都不在笔记仓库里，不随 Git 提交或同步，也不进诊断包；换设备需要重新开启。
- **失效条件**：修改口令或重建密钥库后本机条目自动作废并清理（需要重新开启）；Android/iOS 在系统新增生物识别后由平台使密钥失效，同样要求重新开启。
- **关闭方式**：设置里点「关闭快速解锁」立即删除本机条目与标记，回到「每次输入口令」。关闭后应用内不再有任何免口令入口。
- **档位说明**：开启后，拿得到本机安全存储访问权的本地进程即可读到主密钥——本机防护档位与 GitHub Token 相同（关闭时严格更高）。远端（GitHub 网页、其他 Git 客户端、协作者）的防护不受影响，仓库里始终只有密文。
- 方案与各平台强度差异见 `docs/QUICK_UNLOCK_PLAN.md`。
